1. Endpoint /hr/tambah-cuti: Tambah & Kurangi Cuti
----------------------------------------------------------
- `POST /hr/tambah-cuti` sekarang menerima `jumlah_hari` (positif = tambah, negatif = kurangi) berlaku untuk semua user (karyawan, pm, hr_manager, staff_hr)
- Validasi:
  - `jumlah_hari` tidak boleh 0
  - Saat kurangi: `total_cuti` hasil akhir tiap user harus ≥ 12 (jatah dasar negara tidak boleh dipotong di bawah 12)
  - Saat kurangi: `sisa_cuti` user manapun tidak boleh menjadi negatif
- `total_cuti` dan `sisa_cuti` selalu diubah seragam (+= jumlah_hari)
- Audit tetap tersimpan di `log_cuti_ekstra` dengan `jumlah_hari` negatif untuk pengurangan
- Pesan error kurang dari 12 tidak menyebutkan nama user (berlaku untuk semua)

File yang diubah:
- app/schemas/log_cuti_ekstra.py - `LogCutiEkstraCreate` tambah field `jumlah_hari` + validator tidak boleh 0
- app/services/tambah_cuti_service.py - `tambah_sisa_cuti_semua` dukung nilai negatif + validasi hasil akhir total_cuti ≥ 12 dan sisa_cuti tidak negatif
- app/routers/hr.py - kirim `data.jumlah_hari` (hapus hardcode 1)

2. Split Endpoint Reset Password (Forgot vs Reset Default)
----------------------------------------------------------
- `POST /auth/reset-password` diubah: body `{ "id_user" }`, langsung set password ke default `untukdevajaya` tanpa token/log - akses hanya hr_manager, staff_hr, direktur (via `require_role`)
- Endpoint baru `POST /auth/confirm-reset-password`: body `{ "token", "password_baru" }`, logika lama reset password via form (password pilihan user)
- Validasi token dipindah ke helper `_get_valid_reset_token()` (dipakai confirm-reset-password)
- Forgot password (halaman form via email) terpisah dari reset-to-default (tombol di FE)

File yang diubah:
- app/routers/auth.py - Split endpoint + helper `_get_valid_reset_token()` + role guard di reset-password
- app/schemas/user.py - Ganti `ResetPasswordByTokenRequest` → `ResetPasswordRequestById` (`id_user`)

8. Forgot Password: Input Username (bukan Email)
----------------------------------------------------------
- `POST /auth/forgot-password` sekarang menerima `{ "username" }` (sebelumnya `{ "email" }`)
- Lookup user by username; jika ada dan punya email -> buat token + kirim link reset ke email user tsb
- Anti-enumerasi tetap: response sama untuk username ada/tidak ada -> "Jika username terdaftar, link reset password telah dikirim"
- Token, expiry 30 menit, halaman reset, email link TIDAK berubah
- Catatan FE: form lupa-password harus ganti field email -> username

File yang diubah:
- app/schemas/user.py - `ForgotPasswordRequest.email` -> `username`
- app/routers/auth.py - Query `User.username == data.username` + pesan response
- tests/test_forgot_password.py - 3 test: username ada, tidak ada, tanpa email


9. Pengajuan Kerja: Flow & Final Status Disamakan dengan Cuti
----------------------------------------------------------
- Reversal sebagian changelog 2026-09-13 (eskalasi staff_hr→direktur dihapus): flow & final status kini identik dengan cuti

| Role Pengaju | Flow |
|---|---|
| Karyawan dept≠1 | menunggu_pm → menunggu_hr → disetujui_hr (FINAL) |
| Karyawan dept=1 / PM / staff_hr | menunggu_hr → disetujui_hr (FINAL) |
| hr_manager | menunggu_direktur → disetujui_direktur / ditolak_direktur (FINAL) |
| Direktur | ❌ Tidak boleh mengajukan |

- Final status baru di enum: `disetujui_direktur`, `ditolak_direktur` (paritas `log_cuti`)
- Kolom baru `log_penambahan_kerja`: `diproses_direktur` (FK users) + `processed_at_direktur` (paritas `diproses_hr`)
- Self-approval: approver tidak bisa memproses pengajuan sendiri → 400 (sama seperti cuti)
- Queue HR & Direktur: kecuali pengajuan sendiri (sama seperti `get_queue_card` cuti)
- Alasan penolakan PM decline kini persist ke `alasan_penolakan` (sebelumnya hilang → email kosong)
- Konsumen status di-update ke 3 final (`disetujui_pm` legacy, `disetujui_hr`, `disetujui_direktur`):
  - holiday quota: eksklusi potongan cuti bersama untuk kerja final di semua role (tanpa lagi filter dept-3)
  - dashboard HR: menunggu/diacc/ditolak per role; rekapitulasi HR: `approved_by` baca `diproses_direktur` untuk status direktur
  - PM dashboard ("sedang kerja") + rekap tim
  - schemas `PenambahanKerjaOut` / `HRLogPenambahanKerjaOut` Literal status
- Migration `e7a8b9c0d1e2`:
  - ALTER enum MySQL + add 2 kolom + FK
  - Backfill: `disetujui_hr`/`ditolak_hr` yang diproses user role 'direktur' → `disetujui_direktur`/`ditolak_direktur` (+pindah `diproses_hr`→`diproses_direktur`)
